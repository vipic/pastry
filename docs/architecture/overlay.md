# 浮层与交互架构

> 核对日期：2026-09-03；源码基线：`a5691d8`。静态实现快照，非真实 UI 验收记录。相关选择见 [ADR-002：NSPanel Overlay vs SwiftUI Window](../adr/002-nspanel-over-swiftui-window.md)。

## 职责与边界

浮层模块负责在不切断目标应用工作流的前提下展示剪贴板历史，并协调键盘、搜索、筛选、选择、预览、拖拽和跨应用粘贴。持久化查询由 `StoreManager` 和 `DatabaseManager` 提供，剪贴板读写由 `ClipboardMonitor` 与 `PasteboardWriter` 提供；这些能力不属于浮层内部实现。

## 关键类型

- `ClipboardOverlayPanel`：允许成为 key 的非激活 `NSPanel`，统一处理 Esc、搜索快捷键和需要进入 AppKit responder chain 的事件。
- `OverlayPanelManager`：创建、复用、显示和隐藏面板，保存上一个前台应用，协调粘贴、拖拽穿透、Quick Look 和失焦收起。
- `OverlayView`：SwiftUI 内容树，组合工具栏、卡片带、搜索、筛选、确认层及生命周期通知。
- `OverlayKeyboardRouter`：本地键盘 monitor；按当前键盘所有者把事件交给搜索框、备注编辑器或卡片导航。
- `SelectionState`：与 UI 框架无关的单选、散选、区间选择和光标状态机。
- `OverlayInteractionModel`：把鼠标修饰键和点击转换为可测试的选择行为。
- `SmartActionPanelManager` / `SmartActionPanelView` / `MultiSmartActionPanelView`：从单条卡片或多选工具栏打开独立智能操作窗口，协调 Vision 文字识别、动作选择、设备端草稿生成、编辑确认及日历或邮件执行。

## 面板生命周期

源码入口：[OverlayPanelManager](../../Sources/Pastry/UI/OverlayPanelManager.swift)、[OverlayView](../../Sources/Pastry/UI/OverlayView.swift)、[键盘路由](../../Sources/Pastry/UI/OverlayKeyboardRouter.swift)、[选择状态机](../../Sources/Pastry/UI/SelectionState.swift)。面板回归见 [OverlayPanelManagerTests](../../Tests/PastryTests/OverlayPanelManagerTests.swift)。

1. 全局快捷键或菜单栏入口调用 `OverlayPanelManager.show()` / `toggle()`。
2. 管理器记录当前前台应用，并在鼠标所在屏幕创建或复用与托盘实际范围相同的 `ClipboardOverlayPanel`；面板外区域不会拦截其他应用的鼠标交互。
3. 面板使用 `.borderless`、`.fullSizeContentView` 和 `.nonactivatingPanel`，层级为 `.popUpMenu`，并加入所有 Space 和全屏辅助窗口。
4. 托盘顶部非按钮区域提供停靠拖拽；窗口本身不跟随指针平移。鼠标在拖拽区域按下时，当前托盘立即以贴边方向为锚点整体轻微缩放至 98.5%，无需等待指针产生位移；松手或取消时恢复，明确反馈拖拽手势已经被接收。指针进入与目标托盘同尺寸的左、右或底部投放区域后，会显示半透明虚线目标框；只有在框内松手才切换当前显示会话的布局并贴到对应边缘，离开目标框则取消预览。拖拽停靠不改写设置中的固定位置。
5. `OverlayView` 接收 `overlayWillShow`，恢复默认选择、预取图标并执行入场状态。
6. 未固定时，Esc 或失焦最终请求 dismiss；视图先完成退出状态，再由管理器清理 monitor、预览和面板状态。
7. 工具栏“固定”只维持当前显示会话：面板失焦后留在屏幕上，且不重新抢占 key window；显式关闭会解除固定。
8. 粘贴路径先确认辅助功能权限、挂起剪贴板监听、激活当前目标应用并暂时隐藏面板，再写回剪贴板和投递粘贴快捷键；固定状态下操作完成后在原停靠位置恢复。

启动后会使用一个不可交互、近乎透明的临时面板预热 `NSHostingView`、材质和卡片首帧布局。预热面板不能进入正常事件和诊断生命周期。

## 键盘与关闭层级

键盘所有者只有三种：面板导航、搜索框和收藏备注编辑器。文本输入拥有键盘时，普通编辑键必须交还系统；卡片级快捷键只在面板导航态消费。

Esc 按当前 UI 层级逐层处理：确认层、备注编辑、筛选、Quick Look、搜索，最后才关闭面板。打开或关闭空搜索只切换输入态，必须保留当前卡片选择和滚动位置；输入或清除查询导致可见结果集合变化时，才由结果监听统一回到新列表起点。关闭搜索只清空搜索关键字并退出输入态，保留来源、类型、时间、备注等结构化筛选；这些筛选只由筛选气泡中的明确清除操作或面板整体重置移除。同一次 Esc 关闭 Quick Look 或备注编辑后可能级联触发第二次 cancel，管理器用短暂的吞键窗口阻止面板被一并关闭。

面板通过 `NSWindow.didResignKeyNotification` 自动收起。固定时失焦不会收起或抢回焦点，用户可以直接操作其他应用；Quick Look 正在显示或刚关闭时会暂时保留面板并重新取得 key；粘贴、确认层和拖拽穿透期间不会走普通失焦收起路径。

搜索框保留输入即执行的普通关键词搜索。只有用户在设置中开启苹果智能总开关后，才显示单独的智能找回按钮；按钮仅在用户点击后请求设备端模型解析描述、执行本地语义召回并重排候选。运行中、已应用、模型不可用和失败状态由按钮图标及辅助说明反馈。编辑查询或清除筛选会使旧结果失效，避免迟到的异步结果覆盖新输入。工具栏筛选按钮、All/Favorites 标签及筛选气泡内各标签的选中态统一使用共享的品牌暖棕加深色背景与白色图文。

## 智能操作

苹果智能总开关同时控制智能找回和卡片智能操作。关闭时，文本、RTF、HTML 和图片卡片右键菜单中的“智能操作…”及多选工具栏入口保持禁用；开启后单选支持类型可打开独立可激活窗口。多选 2～10 条文本或图片记录时，工具栏入口根据纯文本、纯图片或图文混合选择展示动态操作；包含文件或超过上限时保留禁用入口并说明原因。单卡文本直接展示记录正文；单卡图片先展示缓存缩略图，不自动分析，只有用户选择具体操作后才读取缓存原图。

图片操作按能力分流：提取文字按需执行 Vision `VNRecognizeTextRequest`，二维码与条码识别执行 `VNDetectBarcodesRequest`；macOS 27 及以上且设备端模型声明支持视觉输入时，还可把原图作为 Foundation Models `Attachment` 生成客观图片描述。OCR 无结果时可以使用采集时随图片保留的文字附注。总入口要求苹果智能开关已开启；进入窗口后，图片描述继续检查对应设备端模型能力。

`LocalSmartActionGenerator` 按用户选择使用独立的结构化生成 schema：总结、改写和自定义指令只产生文本；其中改写最多读取 8000 个字符，并要求在不改变事实和含义的前提下改善清晰度、自然度和简洁度。日历事件产生标题、起止时间、地点和备注；邮件产生收件人、主题和正文。正文是不可信数据，不能选择动作或触发执行。相对日期使用记录采集时间和当前时区解析，日期与时间证据必须能在原文中找到。

`MultiSmartActionGenerator` 复用单卡结构化生成器和图片分析器。纯文本提供综合总结、比较异同、合并重写、逐来源提取日程、拟定邮件和自定义；纯图片提供批量 OCR、条码识别和能力可用时的逐张描述；图文混合只提供总结、提取全部文字和自定义。需要模型理解图片文字时先串行执行 OCR，再按原选择顺序构建带 `<item index>` 边界的输入；总正文最多 3200 个字符并在来源间公平分配，降低单条长内容挤掉其他来源的风险。输出中的 `[编号]` 与选择顺序对应。日程按来源分别生成候选并逐条确认，模型调用和图片分析不并发轰击设备端服务。

单选与多选面板的原始内容区都采用紧凑固定高度，长文本在区内滚动，图片等比缩放，以优先保证草稿和结果的可用空间。多选面板顶部的来源编号是可横向滚动的切换器，下方预览区始终显示当前编号的原始内容，处理阶段和结果阶段都不移除。文本只在用户切换到对应来源时异步读取数据库全文并缓存于当前面板会话，避免一次载入最多十份长正文；图片优先读取缓存原图。结果中的来源编号与该切换器保持一致，使用户可以在不离开面板的情况下核对模型输出。多选初始选择阶段保留三列操作网格；进入自定义、处理或结果阶段后改为可横向滚动的单行操作条，并高亮当前操作，以释放中间结果区高度。

文本的五个操作和图片最多三个操作固定在窗口底部，以单行等宽横向托盘排列；各操作图标使用共享的品牌暖棕加深色背景与白色图形。原文、原图、处理状态、草稿和结果位于托盘上方，处理状态按当前操作显示。文本原文使用固定高度的可滚动视口，处理阶段切换不会改变原文区高度；自定义指令拦截无修饰键的 Return 执行生成，Shift + Return 继续交给多行输入框插入换行。文本面板的阶段内容使用独立纵向滚动区，日历或邮件草稿超过剩余高度时滚动而不挤走原文或底部操作托盘；主操作按钮沿用相同的高对比配色。所有草稿和图片分析结果都先进入可编辑确认状态。OCR 与条码结果完整保存在结果字段中，不做行数截断；内容超过窗口时由隐藏滚动指示器的面板继续承载。文本结果仅在用户点击后复制；日历事件仅在用户点击确认后通过 EventKit 请求仅写权限并保存到默认日历；邮件通过系统 `NSSharingService.composeEmail` 撰写服务打开草稿，不指定具体邮件客户端，也不发送。异步图片分析或生成在切换操作或窗口关闭时取消，防止迟到结果覆盖当前状态。

## 选择与拖拽

`SelectionState` 是选择行为的事实来源。`OverlayView` 只负责从键盘或鼠标事件获取意图，再把可见条目顺序交给状态机。

单选和多选拖拽都使用 SwiftUI `.onDrag`。多选时由 `DragPayloadBuilder.providerForSelection` 生成一个多行文本 `NSItemProvider`；不要在卡片上重新引入 AppKit 事件覆盖层，因为覆盖层会截获 mouseDown，破坏 Command/Shift 选择。

卡片拖拽开始后，`beginDragThrough()` 让面板忽略鼠标事件并立即 `orderOut`，持续检查鼠标按键释放：普通状态完成清理，固定状态则恢复原停靠位置，使用户可以连续向目标应用拖入多个素材。

## 渲染不变量与已知限制

- 面板层级保持 `.popUpMenu`；`.screenSaver` 会破坏 `NSMenu` 右键事件链。
- 透明面板中的托盘背景使用 `NSVisualEffectView(.hudWindow)`，托盘本身不绘制投影，使底部和左右停靠保持一致；紧凑模式悬停轻操作的独立底板使用 SwiftUI Liquid Glass。
- 材质 view 必须启用 layer、裁剪圆角并关闭 layer 阴影，避免圆角外残留暗边。
- 受最大高度约束的内容需要显式 `.clipped()`，否则 SwiftUI 子视图仍可能绘制到 frame 之外。
- 横向卡片带使用 SwiftUI `ScrollPosition` 坐标连续滚动，并用 `onScrollGeometryChange` 限制内容边界；侧滚轮限制单次位移用于微调，普通滚轮映射到横向并保留设备加速，传统滚轮只做一次行距换算。AppKit 桥接只接管发往托盘面板本身的滚轮事件；筛选 popover、设置窗口等独立窗口保留系统滚动链，因此来源应用列表会优先纵向滚动。实现不遍历或直接修改 SwiftUI 私有的 `NSScrollView` 层级。
- 底部托盘在宽屏使用横向卡带；左右托盘固定使用 272 pt 宽的紧凑纵向列表，面板连同两侧 inset 共 296 pt，不再提供完整卡片与紧凑列表的切换开关。每次显示托盘都按设置中的固定位置重新布局，并重置到当前结果列表起点：底部卡带回到最左侧，左右托盘回到最顶部，避免复用面板时继承上次滚动位置。侧边搜索展开宽度必须从固定托盘宽度扣除卡片容器内边距、头部内边距和右侧工具按钮，不能反向撑宽托盘。纯文本和富文本保持全宽文字布局；链接显示抓取的网页标题和链接地址；带图片的 HTML、图片记录与单文件在右侧使用 92 pt 宽的预览，左侧沿用类型、名称、时间和来源应用布局；多文件不显示右侧大预览，改为文件图标和名称纵向列表。侧边头部把搜索与设置按钮相对托盘外框保持 14 pt inset，使 10 pt 控件圆角与 24 pt 托盘圆角共享圆心。所有条目的悬停轻操作始终锚定右下角并共用同一组内边距和 Liquid Glass 底板；底板由系统根据下方内容自动调整明暗，左右分栏条目可直接覆盖在预览区域上。侧边视图与底部卡带共用选择、拖拽、收藏、复制、删除、右键菜单和键盘导航。拖拽停靠只在当前显示会话内生效；关闭后再次打开时始终恢复设置面板选择的位置。
- 侧边栏选择不依赖 `NavigationSplitView` 中的 `List(selection:)`，当前设置导航使用显式按钮状态。
- `OverlayKeyboardRouter` 在应用失去激活状态时必须清除 Command 角标状态，因为用户可能在切换到其他应用后才松开修饰键，当前进程收不到对应的 `flagsChanged`。
- Command 数字快捷选择以 `onScrollTargetVisibilityChange` 报告的当前视口卡片为准，再按筛选结果顺序稳定编号 1–9；角标显示与 `⌘1`–`⌘9` 粘贴必须消费同一组 ID，不能回退到整个结果列表的开头。
- 面板相关状态和 AppKit 调用保持在主线程；不要从后台线程读写键盘所有者或布局状态。
